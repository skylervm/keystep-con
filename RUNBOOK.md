# Runbook

## Where it runs
Local firmware-building tools and emulator tests. The resulting firmware runs on the controller after separately approved installation through Arturia MIDI Control Center. The Live bridge runs inside Ableton Live. No container, service port, server deployment, or hosted installer is configured for this fork.

## Secrets
None required for local building or tests. Repository/tracker administration uses existing authenticated tools. Never put credentials in this repository.

## Build and test
Use Python 3.10+ and clang with the ARM target. Create an ignored `.venv`; install the existing `requirements.txt` dependencies. Place your own official `keystep-pro_Firmware_Update_2.5.20.0.kspf` in ignored `firmware/`. Extract its stock image entries for the emulator fixtures with `python3 -m zipfile -e firmware/keystep-pro_Firmware_Update_2.5.20.0.kspf firmware`. From the repo root, run `PYTHON="$PWD/.venv/bin/python" CHROME="/path/to/chromium" sh scripts/build-firmware.sh` with an installed headless Chromium executable. The script builds both model images, runs original/Chroma Con regressions, tempo/parser/display tests, fake-Live integration tests, and the browser package equivalence check. No MIDI permissions are granted by these checks.

The candidate is `firmware/patched/KSCON_2.5.99_build10.kspf`; the adjacent JSON records the exact stock input and output/model hashes. Firmware, compiled dumps and environment files are ignored. Repeating a build with the same inputs/toolchain should reproduce the package hash. The web patch data contains only changed bytes and is regenerated by this script.

## Live bridge
After review and separate device approval, copy the `KeyStepPro_Transport` folder into the Live User Library's `Remote Scripts` directory, preserving a backup of the existing script. Restart Live only with the user's permission. In Settings > Link, Tempo & MIDI choose KeyStepPro_Transport with both Input and Output set to KeyStep Pro. Keep Live as clock master: KeyStep input Sync off, output Sync on. Preserve other routing. The existing MMC transport handling is retained.

The bridge sends current BPM immediately on changes and once per second. It receives relative knob turns, using 1 BPM normally and 0.01 BPM with Shift, within Live's 20–999 BPM range. A per-instance token rejects old queued turns. Both native BPM views display host tempo without changing saved project tempo. Menus and note popups keep their screen. The 3-second lease expires if the bridge disappears, restoring stock knob behavior and scheduling the stock BPM display from the main loop. USB reception only publishes state; foreground readers copy a complete snapshot with a brief interrupt mask, then restore the prior mask before UI work. USB clock synchronization still drives sequencer timing during playback; display feedback does not change clock source or project settings.

This relies on Live's `_Framework` interfaces. Offline fake-Live tests pass; actual loading in the current Live 12 beta, physical transport/knob/display behavior, and timing still require device validation.

## Deploy and restart
A push or merge does not flash hardware. Do not run device-writing helpers as tests. No new firmware installation is authorized until the exact reviewed package receives explicit flash approval. A device restart is a physical operation coordinated with the user.

## Logs and health checks
Use offline emulator test output and package verification reports. A valid checksum alone is not a compatibility check. Confirm model selection, input hash, patch-site instructions, memory limits, and that the intended model images actually changed. After an approved installation, check the device identity/version and global settings against the private backup.

## Common failures
- Chroma stays stock after an upstream Con install: upstream patches only the original-model images. Do not bypass model headers or flash the original-model image onto Chroma.
- Input hash, image size, instruction, or checksum mismatch: stop. Use the supported official input; vendor updates require a new compatibility pass.
- Offline tests cannot establish safe code/RAM locations: report the evidence and hold the firmware build.

## Dependencies
Python, ARM-capable clang, Unicorn and Capstone. Node and a headless Chromium browser are used by upstream web checks. See `requirements.txt` for existing Python test dependencies.

## Backup and rollback
Keep stock firmware, project backups, and a native global-settings export outside this repository. Backups are private and must not be committed. Reinstalling an official compatible package through MIDI Control Center is the intended rollback path; boot failure recovery is not guaranteed and requires device-specific instructions. Firmware rollback does not replace project/settings backups.

## Upstream maintenance
Upstream: https://github.com/canadianblaken/keystep-con . Chroma mapping reference: https://github.com/yonie/keystep-mods . Validate every borrowed address against the exact supported image. Keep original and Chroma maps separate; never assume one constant address shift.
